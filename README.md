# Notice Board for Nextcloud

**English** · [Türkçe](README.tr.md)

Notice Board (`noticeboard`) is a Nextcloud app for publishing company announcements. Designated
publishers write announcements in a rich-text editor and target them at everyone or at selected
groups. Readers find them in the app, in three dashboard widgets, in unified search, and through
notifications, the activity stream or e-mail.

- **Nextcloud:** 30 to 36 (APIs verified against 32, 33, 34 and 35; live-tested on 35). The App Store requires an upper limit; it is raised with each new Nextcloud release
- **PHP:** 8.1+
- **Frontend:** Vue 3 + `@nextcloud/vue` 9
- **Languages:** English, Turkish
- **License:** AGPL-3.0-or-later

---

## Features

### Writing announcements
- Rich-text body (bold, italic, underline, strike-through, headings, lists, quotes, code blocks,
  links, text colour, highlight). A live preview beside the form shows exactly what readers will see.
- **Cover image** picked from your Nextcloud files. You set the **focal point**: click or drag on the
  image, and that spot stays visible wherever the cover is cropped (detail banner, list thumbnail,
  card widget).
- Up to 20 **attachments** from your files.
- **Category**, **priority** (normal / important / urgent) and **pin to top**.
- **Drafts**, **scheduled publishing** and **automatic retirement** at a set time.

### Audience
- **Everyone** or **selected Nextcloud groups**. Users who aren't targeted never see the
  announcement anywhere: not in the list, widgets, search, notifications or by guessing its URL.

### Delivery (toggled per announcement)
| Option | What it does |
|---|---|
| Activity stream | Adds a "published an announcement" entry to the Nextcloud *Activity* feed of every targeted user |
| Notifications | Sends a bell-icon notification; it is withdrawn automatically when the announcement is deleted or expires |
| E-mail | Queues an e-mail to targeted users (needs a working SMTP setup) |
| Comments | Lets readers comment under the announcement (uses Nextcloud's core comments) |

Delivery happens **only when an announcement goes live**. Fixing a typo in a published
announcement does not notify everyone again.

### Reading
- App page with a list and detail view, paging, and permanent links (`/apps/noticeboard/#/announcement/<id>`).
- Three **dashboard widgets**: *Notice list*, *Notice cards* and *Notice slider*.
- **Unified search** provider (top search bar). Results respect targeting and scheduling.

### Who can publish
Nextcloud administrators can always publish. They can also allow specific **users** or **groups**
under **Administration settings → Notice Board**. A publisher can edit and delete only their own
announcements; administrators can edit any announcement.

## Installation

The compiled JavaScript (`js/`) is not committed, so build the app before installing it.

```bash
git clone https://github.com/SafiCeylan/Notice-Board.git noticeboard
cd noticeboard
npm ci
npm run build
```

Copy the folder to your Nextcloud `apps/` directory under the name **`noticeboard`**. The folder name
must match the app id. Then enable the app:

```bash
sudo -u www-data php occ app:enable noticeboard
```

Scheduled publishing and automatic retirement run as a background job every 5 minutes. Use
**cron** for background jobs (`occ background:cron`) so that they run on time.

### Upgrading
Copy the new files over the old ones. If the version in `appinfo/info.xml` changed, run
`occ upgrade` to apply the database migrations.

## Development

```
appinfo/     app manifest and routes
lib/         PHP: controllers, services, mappers, migrations, widgets, search, activity, notifications
src/         Vue 3 frontend (app, admin settings, dashboard widgets)
l10n/        translations (generated by build-l10n.py)
tests/       PHP test suites (run without a Nextcloud instance)
```

| Command | Purpose |
|---|---|
| `npm run dev` / `npm run watch` | Development build |
| `npm run build` | Production build |
| `./run-tests.sh` | PHP syntax check, `info.xml` validation, translation completeness and all unit tests |
| `./mutation-check.sh` | Breaks security rules on purpose and checks that the tests catch each break |
| `python build-l10n.py` | Regenerates `l10n/` from the strings used in `src/` and `lib/` |

`run-tests.sh` reads the PHP binary from the `PHP` environment variable, for example
`PHP=/usr/bin/php ./run-tests.sh`.

The source language of the UI strings is Turkish. The English translations are in `build-l10n.py`.
If you add a string, add its English version there too, or the translation check fails.

### Security model
- Permission checks live in exactly two places: `PublisherService` (who may write) and
  `VisibilityService` (who may read). Every read path goes through
  `AnnouncementService::findEntityForReader()`.
- Announcement HTML is sanitised **when it is written** (`HtmlSanitizer`), against an allow-list
  that matches the editor toolbar.
- Cover images and attachments are served according to the announcement's visibility, not the
  author's file permissions. An attachment is also checked to belong to the requested announcement.
- On read endpoints, "no access" and "does not exist" return the same 404, so IDs cannot be enumerated.
- Creating announcements (30/hour) and comments (60/hour) is rate-limited per user.

`tests/SecurityContractTest.php` scans the source and fails if a new endpoint skips these rules.
